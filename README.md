# 관객-반응-디피 시스템 (관반디)

관객의 한 줄 반응을 접수하고, 운영자가 검수·표시 문구 편집·회차 배정·상영을 제어하는 웹앱입니다. Node.js 내장 HTTP·SQLite와 기존 정적 HTML/CSS/JavaScript를 사용합니다. 외부 API 키, 클라우드 계정, npm 런타임 패키지 및 별도 프런트엔드 빌드가 필요하지 않습니다.

AX4U가 MIT License로 공개하는 오픈소스 프로젝트입니다. 소스 이용·수정·재배포 조건은 `LICENSE`를, 별도 SIL OFL 1.1이 적용되는 동봉 폰트는 `THIRD-PARTY-NOTICES.txt`와 해당 고지 전문을 참조하세요.

저장소: https://github.com/ax4u/gwanbandi

실제 참가자 정보를 받는 인터넷 운영 전에는 아래 ‘알려진 운영상 제한’을 반드시 검토하세요. 소스 공개는 운영 개인정보 처리·공연·미디어 재배포 승인을 대신하지 않습니다.

## 빠른 로컬 실행

Node.js 22.13 이상이 필요합니다. Node.js 26.8.1에서 실제 격리 검증했습니다. 내장 SQLite는 일부 Node 버전에서 실험 기능 경고를 출력합니다. Linux/macOS 터미널 기준이며 계정 발급은 `/dev/tty`가 있는 환경이 필요합니다. Windows에서는 WSL을 사용하세요. 다른 OS는 미검증입니다.

다운로드한 디렉터리에서 실행합니다.

```sh
cp .env.example .env
npm start
```

새 `data/`에 빈 DB와 임의 관리자 키가 생성됩니다. 운영 DB·계정·사연·음원은 동봉하지 않습니다. 기존 운영 경로를 `DATA_DIR`로 지정하거나 DB를 복사하지 마세요. 기본 포트가 사용 중이면 `.env`의 `PORT`, `ADMIN_PORT`, `PUBLIC_URL`을 함께 변경하세요.

- 관객 접수: http://127.0.0.1:18991/jungang-memory/
- 행사 관리: http://127.0.0.1:18991/jungang-memory/manage/
- 표시 전용 프로젝터: http://127.0.0.1:18991/jungang-memory/screen/?view=projector
- 별도 로컬 관리실: http://127.0.0.1:18992/control/

제품 이름과 별개로 `/jungang-memory/`, 내부 event ID, 쿠키·동의 버전 식별자는 기존 코드 호환성을 위해 유지했습니다. `/`에서는 앱을 제공하지 않습니다. `localhost`와 `127.0.0.1`을 혼용하면 Origin 검증이 거부하므로 `PUBLIC_URL`과 같은 주소를 사용하세요.

## 새 관리 계정 만들기

서버를 실행한 뒤, 동일 폴더의 두 번째 실제 대화형 터미널에서:

```sh
npm run account -- issue
```

기존 TTY 확인·본인 전달 동의·유효시간 입력을 따른 후 임의의 긴 계정/암호가 터미널에 한 번 표시됩니다. 이 계정으로 관리 화면에 로그인합니다. 화면 녹화·로그 저장·채팅 전송·명령 인자에 암호 입력은 하지 마세요. `issue` 계정은 최대 7일, 웹 로그인 세션은 최대 8시간입니다. 만료 후 계정 신규 발급이 필요합니다. 파이프·비대화형 실행은 의도적으로 거부합니다.

기존 `rotate`, `revoke`, `issue-short`, `unlock` 기능도 그대로 있지만, 추측 공격 위험 때문에 짧은 계정은 권장하지 않습니다. `node --env-file-if-exists=.env deploy/admin-access.mjs`는 로컬 관리실 키를 실제 터미널에서만 확인하는 기존 보조 도구입니다. `ADMIN_PORT`는 외부에 노출하지 마세요.

자동 검사는 새 임시 DB와 임의의 테스트 전용 계정만 사용합니다. 실제 운영자 TTY 발급 절차 전체를 자동 입력하여 우회하지 않습니다.

## 접수 → 검수 → 상영

1. 관리 화면에서 활성 접수 회차(1/2)와 상영 회차를 확인합니다. 둘은 별개입니다. 접수 도중 회차가 바뀌면 다시 확인해야 합니다.
2. 관객은 첫 문항·별명·공개/보관 동의와 낭독 의사를 제출합니다. 첫 문항은 2~120자, 별명은 16자, 두 번째 응답은 500자까지입니다. 전화번호·이메일·HTML 입력은 제한합니다. 자동 검사가 모든 개인정보를 식별하지는 못합니다.
3. 최신 정책에서는 새 동의 글이 접수 즉시 상영 가능 상태가 됩니다. 검수 대기 후 공개되는 제품으로 오해하지 마세요. 기존 ‘승인 ON/OFF’는 호환 보존용이며 신규 자동 공개를 끄지 않습니다. 운영자는 검수 메뉴에서 대기/상영 불가로 숨기고 표시 문구를 편집할 수 있습니다. 원문은 별도 보존합니다.
4. 관리 화면에서 명시적으로 상영 시작을 누릅니다. 무작위 간격은 회차별 1~60초(새 DB 기본 3초). 적용 직후 현재 사연을 넘기지 않고 새 간격을 셉니다. 프로젝터는 약 1초 폴링이므로 정확한 매초 프레임 동기화·무누락은 보장하지 않습니다.
5. 직접 낭독은 상위 5개 또는 전체 낭독 희망자 목록에서 선택/이전/다음으로 수동 진행합니다. 원고(최대 5,000자)와 엔딩 문구는 회차별 보존되며 아래에서 위로 이동합니다. 엔딩에는 현재 회차의 공개 가능한 글 중 크레딧 동의 별명만 포함됩니다.
6. 회차 변경·서버 재시작·로그아웃·인증 만료는 안전정지됩니다. 재로그인·명시적 시작/재개가 필요합니다. 프로젝터에는 로그인이나 운영 제어를 넣지 않았습니다. 관리 창만 닫으면 서버 진행은 인증 유효기간 동안 계속되지만 해당 탭의 BGM은 종료됩니다.

## 기본 배경·음원·라이선스

재배포 권리가 불분명한 기존 이미지·일러스트·사진·QR·음원은 포함하지 않습니다. CSS 중립 배경과 무음이 기본입니다. 기존 Pretendard/Nanum 폰트와 전체 SIL OFL 고지는 보존했습니다. `THIRD-PARTY-NOTICES.txt`를 참고하세요.

선택적으로 공개 제공 권리가 확보된 MP3의 절대 경로를 `.env`의 `BGM_FILE`로 지정하고 서버를 재시작할 수 있습니다. 파일은 저장소 밖에 보관하세요. `BGM_FILE` 미설정이면 오디오 준비 버튼이 비활성화됩니다. 설정한 MP3는 `/jungang-memory/media/bgm/reading.mp3`에서 공개 제공되며 Range 요청을 지원합니다. 경로를 지정하는 것은 권리 허가를 대신하지 않습니다. 파일 변경 시 서버도 재시작하세요.

‘관리자 소리 준비’를 클릭한 관리자 탭에서만 무작위/상위 5개/전체 낭독 중 음악이 재생됩니다. 원고·엔딩·정지 때는 멈춥니다. 탭을 유지하고 실제 스피커 연결은 현장에서 확인하세요. 다른 PC의 프로젝터 소리를 원격으로 허용하는 기능은 아닙니다.

## 설정과 인터넷 배포 경계

`.env.example`은 비밀 없는 로컬 예시입니다. `.env`, `data/`, `*.sqlite*`, 키, 로그는 Git 제외 대상입니다. `.gitignore`는 이미 추적한 파일을 안전하게 만드는 도구가 아니므로 게시 파일 목록을 별도로 검토해야 합니다.

- `PORT` / `ADMIN_PORT`: 모두 127.0.0.1에만 바인딩합니다.
- `PUBLIC_URL`: 정확한 외부 origin + `/jungang-memory/`. 원격 운영은 HTTPS만 허용합니다.
- `DELETION_CONTACT`: 참가자에게 표시할 실제 삭제·동의 철회 문의 창구. 원격 운영에서는 필수입니다. 로컬 기본 안내는 실제 공개 운영용이 아닙니다.
- `DATA_DIR`: 새 독립 데이터 폴더. 기본 `./data`이며 디렉터리 0700, 키/DB 0600으로 생성합니다.
- `BGM_FILE`: 선택 MP3 파일 경로. 기본 미설정.

인터넷 배포용 프록시·DNS·서비스 등록은 동봉하거나 실행하지 않았습니다. 별도 검토 후 HTTPS 리버스 프록시로 공개 포트만 연결하고 `/control/` 및 ADMIN_PORT는 외부 전달하지 마세요. 프록시가 `X-Jungang-IP`를 신뢰된 실제 주소로 덮어쓰고 외부 입력 헤더를 그대로 신뢰하지 않도록 해야 합니다. 외부 HTTP에서 Secure 쿠키를 제거하여 인증을 완화하지 마세요. 로컬 실행은 최신 Chromium의 loopback 보안 예외에서 확인했습니다.

이 앱은 단일 행사·단일 SQLite 프로세스이며 다중 테넌트 서비스가 아닙니다. 여러 프로세스가 같은 DB를 운영하는 구성은 검증하지 않았습니다.

## 데이터 보관과 삭제

새 공개 동의 글에는 자동 만료가 없습니다. 두 번째 응답·원문·표시 수정 이력은 관리자용이고, 숨김은 삭제가 아닙니다. 개인정보 처리 목적·보관기간·철회 창구는 실제 운영 전에 별도로 검토해야 합니다. 새 정책을 기존 응답에 소급 적용하지 않습니다.

CSV에는 비공개 응답과 모든 상태가 포함되므로 승인 없이 공유하거나 공개 저장소에 넣지 마세요. 영구 삭제는 로그인·버전 검증·명시적 확인을 거치며 해당 사연과 수정 이력을 제거합니다. 재전송 복원을 막기 위해 내용 없는 요청 UUID가 남습니다. 백업·CSV 사본은 별도 보관/삭제 정책이 필요합니다. 원본 프로젝트 삭제는 운영 종료나 개인정보 삭제 완료를 의미하지 않습니다.

## 재현 가능한 합성자료 검사

```sh
npm test
```

설치 없이 Node 내장 테스트 러너가 임의 loopback 포트 두 개와 새 임시 DB를 만들고 실제 서버를 실행합니다. 접수·동의 거부·중복 재시도·검수·표시 원문 분리·인증/Origin·CSV·회차 분리·1~60초 간격·수동 낭독·엔딩·안전정지·재시작을 검사합니다. 테스트 데이터만 정리하며 실제 `DATA_DIR`와 `.env`는 읽지 않습니다. `TMPDIR`가 없으면 저장소의 `.test-tmp/`를 사용합니다. 테스트의 대기 시간 검사는 과부하 호스트에서 타이밍 영향을 받을 수 있습니다.

별도 공개용 빌드 단계는 없습니다. 실제 브라우저 화면 검증과 현장 스피커 청취는 서로 다릅니다. 이 저장소의 공개와 실제 운영 서비스 배포는 별개입니다.

## 알려진 운영상 제한

낭독 의사와 질문2는 비공개입니다. 공개 `/jungang-memory/api/state`는 관리자 상태와 별도 허용목록으로 직렬화합니다. 낭독 희망 플래그·상위5/전체 후보 ID·순서·검수문구로 대체된 원문·수정 이력·미상영 원고·설정의 추가 필드를 내보내지 않습니다. 공개 사연 본문은 검수 표시 문구가 있으면 그것만 사용합니다. 관리자의 인증된 목록·CSV·회차별 선택 기능은 유지합니다.

프로젝터에는 현재 상영이 허용된 사연 ID와 동의된 공개 본문·별명, 실제 상영 중인 선택 원고/엔딩 문구만 전달합니다. 무작위·상위5·전체는 공개 응답에서 모두 중립적인 `story` 모드로 표현하며, 후보 순번/총원 표시는 관리자 화면에서만 제공합니다. 정지·로그아웃·인증 만료 때 선택 ID와 원고는 공개하지 않습니다. 일시정지는 기존처럼 현재 화면을 유지합니다. 참여 화면의 ‘담당자만 확인’ 안내와 동의 계약은 바꾸지 않았습니다.

이 경계는 API의 비공개 필드·후보 목록 직접 노출을 차단하는 조치이지, 공개 상영 이력·전환 패턴이나 현장 관찰을 통한 낭독 참여 추론까지 방지하는 보장은 아닙니다. 동의된 공개 본문·별명·크레딧, 운영자가 실제 상영한 원고/엔딩은 익명으로 조회할 수 있습니다. 공개 문구에 개인정보를 직접 넣는 경우도 자동으로 가려 주지 않습니다. 입력 제한만 믿지 말고 검수와 별도 운영 개인정보 정책을 적용하세요. 기존 버전에서 이미 수신한 정보는 회수할 수 없으며, 소스 업데이트가 기존 운영 서비스에 자동 적용되지는 않습니다.

관리 미리보기 CSS에는 제외된 옛 SVG 파일의 비활성 참조가 남아 있습니다. 현재 `story.css`의 중립 배경이 덮어쓰며 해당 이미지 파일은 배포하지 않습니다.
